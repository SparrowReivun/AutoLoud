# AutoLoud：自动响度均衡 — 方案与待决策要点

会议发言稿 · 2026-10-22 · 对应代码 v0.1.0（分支 main）

## 一、我们在解决什么

不同视频、应用之间的音量差异很大，用户需要频繁手动调音量；通话中突然弹出的提示音会吓一跳。目标是一个系统级工具：校准一次，之后切换任何来源都不用再碰音量。下一步在此基础上做多来源并存时的自动混音（音乐、视频、AI 助手、通话之间的比例）。

## 二、技术路线（已修正）

原设想是"像 FxSound 那样接管 Windows 音频输出"。核实后发现 FxSound 本身依赖一个虚拟音频驱动；普通应用无法直接拦截并替换别的应用的音频流。可行路线有三条：虚拟声卡、自定义 APO、以及"监听响度 + 控制音量"。

当前采用第三条：用 WASAPI loopback 回录系统混音，实时计算 BS.1770 响度（LUFS），再通过 Windows 的会话音量（每个应用一个）和主音量把结果对准目标。不装驱动、不改音频流、零延迟，并且天然知道是哪个应用在发声——这正是后续自动混音需要的信息。代价是做不了逐采样的限幅和压缩；后端接口已为将来的虚拟声卡路线预留。

交付物：PySide6 图形界面；本地一键运行脚本；PyInstaller 单文件 exe；GitHub Actions 自动测试、打包、发布 Release。仓库：github.com/SparrowReivun/AutoLoud。

## 三、校准：每个输出设备一套

每个耳机 / 音箱 / 蓝牙设备各自保存一套校准。

1. 用户先把外部设备和 Windows 主音量放到 80% 左右。
2. 音乐 → B（舒适）：播放内置曲目，或用户先用任意应用（Spotify、浏览器等）播放自己的音乐再在向导里选中它，推子直接控制那个应用的音量，从 0 慢慢拉高到舒适。

（原来的"刺耳滴声 → 上限 A"一步已取消，起始下限直接取 B − 5 dB。）B 存的是回录域里的 LUFS 值，而不是推子位置；校准时的主音量一并记录为基准，之后不应再动。向导还会自动探测主音量是否在回录里可见（蓝牙设备通常不可见），这决定增益估计是否会漂移。

## 四、运行时逻辑（已修正）

**起始保护**：仅当从完全静音进入有声时触发。目标响度从 B − 5 dB 出发，2 秒内平滑升到 B，期间在线估计来源响度。突然出现的大音量铃声最多只有 B − 5 dB 那么响。

**已有声音时新增来源**：不回到 A（听感会断），也不单独处理，交给下一次窗口重算。原稿中"如果能识别来源就为每首歌/每个视频单独调一次"目前做不到——能识别的粒度是"哪个进程"，不是"哪首歌"。

**窗口重算**：到达窗末时，用这一窗的积分响度（带门限，排除静音和安静段）计算下一窗的增益，2 秒渐变，然后清空重新累积。起始后第一个窗 12 秒（因为起始段只用了 2 秒瞬时响度，估计粗，要尽快修正一次），之后每 30 秒一窗（原稿为 3 分钟，已缩短）。窗长是在"跟得上切换"和"保留音乐电影内部动态"之间取平衡。

**安全压限**：瞬时响度超过 B + 8 dB 时 0.3 秒快速压下并重置分析窗。这是对窗口重算的必要补充：窗里突然切进来的广告不能等到窗尾才处理；8 dB 的余量是为了不误伤音乐里正常的强弱对比。

**执行方式**：需要衰减时降各应用的会话音量（≤ 0 dB）；需要提升时才把主音量抬到校准基准之上，上限 +12 dB。关闭或退出时全部恢复原样。

## 五、需要大家决策的点

| # | 问题 | 当前取值 | 备选 / 考虑 |
| --- | --- | --- | --- |
| 1 | 安全压限余量 | B + 8 dB | 6 dB 更保守但可能压掉电影爆炸场面；10 dB 更宽松但广告漏过概率增加 |
| 2 | 分析窗长度 | 30 s（首窗 12 s） | 原稿 3 min 保留动态更多但对切换反应慢；也可考虑 60 s |
| 3 | 起始 A→B 渐变时长 | 2 s | 1 s 更快到位，3 s 更柔和 |
| 4 | 起始保护假设的"最坏来源响度" | −10 LUFS | 决定待机时预设多深的衰减；越低越安全，但轻来源起始会更轻 |
| 5 | 主音量最大提升 | +12 dB | 防止把极轻的来源连同底噪一起抬到最大 |
| 6 | 新应用发声后是否快速重估 | 关闭 | 开启后 3 s 用短时响度重估一次；本次已按"统一交给窗口重算"关闭 |
| 7 | 按曲目 / 视频识别来源 | 未做 | 可用 Windows Media Session API 取曲名，切歌时重置分析窗；需评估覆盖面 |
| 8 | 自动混音的场景规则 | 未做 | 通话优先、音乐让路等比例如何定义；需要按进程名做分类表 |
| 9 | 许可证 | CC BY-NC 4.0 | CC 不是为软件设计的（无专利条款）；若要开源协作可改 MIT / GPL |
| 10 | 蓝牙设备主音量不可见时的策略 | 自动探测，按不可见处理 | 探测信号待改为连续正弦以提高稳定性 |

## 六、已验证与已知问题

已验证：响度计与 pyloudnorm 对拍误差 < 0.2 LU；控制器闭环仿真 14 项测试全部通过（起始保护、收敛、渐变平滑、安全压限、无运行时漂移、新增来源不回 A）；真机上稳定运行；GitHub Actions 自动打包成功。

已知问题：mp3 解码在部分环境崩溃（内置曲目已改为 FLAC 绕开）；蓝牙耳机的主音量探测偶有假读数；exe 未签名，首次运行有 SmartScreen 提示。
