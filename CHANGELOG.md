# Changelog

## 0.4.2 — 2026-11-03

- Single-app attribution (source loudness, platforms, per-app preset, `sole_app`) now asks which app *dominates the mix* - loudest by peak x session volume, every other sounding app at least ~10 dB under it - instead of requiring exactly one app over the peak threshold. An idle session hovering at that threshold (OBS's monitor hiss at 100 % while the music sits 30 dB down) kept flipping the source reading to '—'. A new work in an app that is sounding but not the dominant one (a WeChat notification behind the music) no longer re-targets the bus to that app's remembered gain (14:02:19: bus jumped −28.4 → −24.8 dB for a WeChat blip).
- Fix: source loudness often unreadable after lowering P (until a replay or a seek). The loopback measures the mix after the session volumes, so under a deep cut (−50 dB) ordinary content sits at −90 LUFS, below BS.1770's −70 absolute gate, and counted as silence: no source loudness, T fell back to P, platforms stopped learning, no block could be measured so the gain could never climb back, and 15 s of such 'silence' ended the work. The gate now follows the gain the loopback already contains (floored at −105 LUFS).
- Logs moved to a `logs\` folder next to the program (falls back to `%APPDATA%\AutoLoud` when that is not writable). Every mode switch on the dashboard starts a fresh set of adjust / meters / apps / volume files, tagged with the mode in the name (`-monitor` / `-default` / `-strong` / `-strong1`), so one file is one experimental condition.
- Monitor-only no longer runs the gain controller: it kept computing in the background, so the adjust log and meters.csv showed decisions that were never applied, and leaving monitor-only applied that stale gain at once. Monitor-only logs now contain only the user's own moves; leaving it starts the controller afresh.
- New `tools/plot_volume.py`: every volume move the user made in a run (monitor-only / automatic preset in different colours) and AutoLoud's own automatic gain and target T on one time axis, with Chrome's tab titles under the axis.
- Quiet intros no longer get boosted into an overload: in 强力1, a source more than 6 LU under the app's own quiet platform (a fade-in, an intro, a loading screen) is never raised - the gain waits for the content (setting "intro / fade: never raised"). Seen 07:25: an intro at −44 under a −31 platform was raised +9 dB, then the song body hit the protection.
- A new work now starts in the steady state (setting, on): whether it is too loud or too quiet is decided by the steady block counts, not by the first block alone; the first cut still goes all the way.
- Built-in 强力1 follows the author's tuning (steady: 1 loud block over T + 4, 6 quiet blocks under T − 6; protection T + 16; X = 13).
- In monitor-only mode the dashboard's comfort slider becomes a plain Windows master volume control (0-100 %), and the volume keys / knob move the master as Windows normally would; leaving the mode parks the master again and resumes control.
- `volume-<ts>.csv`: one row per volume action the user takes (volume keys / knob, a press Windows handled behind the hook, the P slider, a mixer fader, and - in monitor-only mode - every move of the Windows master), with the mode in force; for counting how often the user still reaches for the volume with and without AutoLoud. In monitor-only mode the keys are left to Windows and the master is not re-parked, so the user's own moves are what gets counted.
- Dashboard mode box has a "Monitor only (no adjustment)" entry: every session goes back to 100 % and no volume is touched (bus, faders, protection, strong pulls) while measuring, learning and the dashboard keep running; settings, faders, presets and remembered gains are left exactly as they are. Remembered on restart.

## 0.4.1 — 2026-11-02

- Dashboard tiles are now: total gain, source loudness (short-term 3 s of the sole sounding app), the loudest app's learned platforms C_low / C_high, target T (with u in 强力1). Session gain and master boost are gone from the tiles (the master no longer moves).
- Built-in presets follow the author's current tuning (强力1: protection T + 16.5, X = 10 LU, 10 s silence); a fresh config starts in 强力1; key step 0.4 dB.
- Dashboard meters and the P slider now run from −90 to 0 LUFS (were −60); the slider's bottom (−90) is mute.
- Exit pop (since the master became managed): a control tick still in flight after the volumes were restored re-parked the master at 80 % under sessions already back at 100 %. Ticks are no-ops once stopping, and stop waits up to 6 s for the thread.
- On exit / crash the Windows master volume is set to 1 % (Settings), and it is set before the sessions return to 100 % - that order was the exit pop. (Restoring the pre-launch master level was dropped: unreliable across crashes.)
- The master level found at start-up is remembered on disk, so it is put back on exit even after a crash left the master parked (before, a second launch saw 80 % and "restored" 80 %). Unhandled Python exceptions and interpreter exit now also put the volumes back. Settings: "master volume to leave on exit / crash (%)" (−1 = the start-up value; e.g. 1 for a near-mute).
- No pop on start or exit: the master is raised to its parked level only after the sessions already carry the parked attenuation, and on exit the master is lowered back before the sessions return to 100 % (whichever move makes things quieter goes first).
- Volume keys in a full-screen game: the keyboard hook cannot see key presses while an elevated window (most games with anti-cheat) is in front, so Windows moved the master itself. Such a master move is now read as the presses it was (2 % per press), P is nudged by the key step per press, and the master is parked again. For that the master is parked at 80 % rather than 100 % (a press must still have somewhere to go); configs at the old defaults are moved once. The key step default is 0.5 dB (was 1 dB; a config still at 1 dB is moved once; Settings).
- The Windows master volume is now managed by AutoLoud (parked at a fixed level; configs still at the old defaults are moved once): every control move is a session attenuation, the master never has to move for a "boost", and the headroom is simply how far below 0 dB the calibration landed. The pre-launch master level is restored on exit so quitting never blasts the headphones. The calibration wizard now says to set the external device a little louder than usual and leave the master alone; the dashboard note about the volume keys is plain text.
- Device switch: no pop and no silence afterwards. The pop was every session being blasted back to 100 % on the way to the new device (now the gain carries over); the silence came from the first buffers of a freshly opened loopback stream containing garbage (values of 1e30) - the meter read +hundreds of LUFS for a moment, the first decision "cut all the way" took the bus to −116 dB, and the 60 s window kept ringing for minutes (readings of −2000 LUFS in the CSV). Such blocks are now dropped and the meter restarted clean; the controller also ignores any reading above +10 LUFS, which no loopback can produce.
- Far from the target the steps are proportional: each step is at least half the remaining error (new preset parameter "step fraction", 0.5; 0 restores the fixed caps), so a block 12 dB too loud is corrected in three blocks instead of six, and a quiet one likewise once the rules decide to adjust at all. The per-step caps still apply near the target.
- Bus ran to its floor (−120 dB) or ceiling after a device switch: the per-session volume objects were cached by process only, so after Windows re-created the sessions (default-device change, Bluetooth re-pair) AutoLoud kept setting - and reading back - the volume of a dead session while the live stream played on untouched; the loudness never answered and the controller cut to the floor. The cache is now keyed by session instance (and device), every session a process holds gets the volume (Chrome has several), and a session whose reported volume drifts from what was set is set again.
- Picking an output device on the dashboard now also makes it the Windows default output (IPolicyConfig, the same call the Sound control panel makes; all three roles), and the activity log says whether Windows applied it. Settings switch "also make it the Windows default output" (on by default).
- Startup master volume default is 50 % (was 40 %; a config still at the old default is moved once). The dashboard now says, under the P slider, that the volume keys / knob move P and no longer the Windows master volume, and where to switch that off.
- 强力1 preset shipped with a fresh config follows the author's current tuning (steady trigger 5, protection T + 18, 0.4 s moves, 30 s silence).
- A new work in an app that is not sounding (a browser tab changing its media title behind a game) no longer re-targets the bus: it used to jump the gain to that app's remembered value and bury whatever was playing (seen 18:28 with chrome.exe behind ZenlessZoneZero: −13.9 dB, 28 s to climb back). The activity log notes "changed work while silent: bus gain left alone".
- Windows build is now a folder (`AutoLoud-windows.zip`, run `AutoLoud\AutoLoud.exe` inside) instead of a single self-extracting exe - the one-file layout is the classic antivirus false-positive trigger ("trojan" warnings reported by downloaders). README explains the warnings and how to verify; docs/RELEASING.md has the false-positive submission steps.
- The 强力1 preset shipped with a fresh config follows the author's current tuning (dead band ±3 dB, steady trigger 3 dB, 2 s moves, X = 16 LU).
- README (all five languages): new intro, principles 5-7 (hearing protection, per-app volume control, enjoy the sound), zip download steps.

## 0.4.0 — 2026-11-02

- New built-in preset 强力1 (source-tracking target): the target T is no longer fixed at B but slides between B − X and B with the sounding app's own loudness - u = clip((L_src − C_low) / (C_high − C_low), 0, 1), T = (B − X) + X·u, X = 5 LU by default. Each app slowly learns its two platforms C_low / C_high (20th / 80th percentile of its source loudness while sounding alone; half-life ~20 min of sounding time; shown in the mixer with a Relearn button; a downward shift of the whole picture - the app's own volume turned down - rebuilds it from the last two minutes). u is refreshed once per listening block from the 3 s short-term reading; while nothing is attributable T is held, after 60 s without a reading it is B again; without ready platforms it is B. New preset parameters: target mode, X, fall-back time, and "strong: cut pulls fader" (the old per-app strong tick). 强力1 ships with a ±1.5 dB dead band so the sliding target is actually followed.
- The per-app "strong mode" tick in the mixer is now a preset drop-down: while that app is the only one sounding, the bus runs with that preset (default: follow the dashboard mode). Apps that had strong mode ticked are moved to a preset named 强力 with the cut-pulls-fader rule on (created from the active preset if there was none).
- Source loudness: when exactly one app is sounding, the loudness of that app with every gain taken out (what it would measure at 100 % session volume and the reference master) is computed from the loopback and its session volume. The dashboard shows it under the meters next to the raw loopback reading ("Loopback as measured" / "Source loudness (app)"), `apps-<ts>.csv` carries it as `src_momentary_lufs` / `src_short_lufs` on that app's rows, and `meters-<ts>.csv` names the sole sounding app in a `sole_app` column. `plot_app.py` draws it as its third panel (derived from session volume for older logs).
- `tools/plot_app.py <app> [run]` plots one app's history from those CSVs (peak meter + session volume, bus loudness with B and the stretches where the app sounded alone, bus gain + fader); needs pandas and matplotlib.
- Naming: the comfort level is now called P (human preference loudness) everywhere in the UI and docs; the rules aim at T (target loudness), which equals P except in the 强力1 mode. Every loudness rule is now relative to T - the onset floor (T − 10) and its end point, the adjust error / comfortable band / one-step snap, the steady loud / quiet triggers, the protection trigger (T + 13) and landing (T + 5), the strong fader pull (T − 5), the slider's one-step move, the meters' distance labels and the log's "(T ±x)". The headline of the activity card and the meters were still measuring against P while the log lines measured against T; both now use T. P itself is only what the slider / volume keys / master-move shift, the mute at the slider's bottom, and the P and X of the 强力1 formula.
- 强力1 steady triggers tightened to ±3 dB (were the ±4 / −15 copied from 强力): with a sliding target a steady bus stayed 7 dB under T without ever re-adjusting. Existing 强力1 presets are patched once if still at the copied values.
- Defaults are the author's tuned 默认 preset (block 2 s, +1.3 / −2 dB steps, +2 / −3 dB dead band, snap 3 dB, steady re-adjust after 1 block over T + 4.5 or 3 blocks under T − 16, protection at T + 14 → T + 2 in 0.05 s, 0.4 s moves, master boost up to 40 dB); a fresh config ships three presets: 默认, 强力 (bolder steps, protection T + 12 → T + 5) and 强力1 (source-tracking target, ±2 dB dead band, steady 2 blocks over T + 5 / 4 blocks under T − 6). Existing configs keep their own presets.
- The target marker T is drawn on all three meters; the dashboard mode box shows "→ preset (app)" while an app's own preset drives the bus.
- Capture watchdog: the WASAPI loopback stream can die quietly (seen with AirPods: a Bluetooth re-negotiation at 12:42 froze the meters for 26 minutes while the rules kept acting on the last reading). Now a reading older than 2 s counts as silence, and while some app's own meter says it is sounding the capture is reopened (every 5 s until it works), following the current default device if the chosen one is gone.
- Bluetooth headset re-connected → the loopback could not be reopened ("Invalid sample rate" every 5 s for ever): PortAudio enumerates devices once at start-up, and after the headset re-pairs that list is stale. Opening the loopback now retries once on a fresh PortAudio instance (device list re-enumerated), and the capture watchdog refreshes it before every retry that follows a failure.
- Windows service sessions (svchost.exe, audiodg.exe, System sounds) no longer count as "an app sounding": with a Bluetooth headset svchost.exe carries a session whose meter moves with the music, which made every app look like it was never alone - no source loudness, no platforms, no per-app preset.
- A Core Audio call that does not answer within 5 s no longer restarts the COM worker at once (the audio service often just stalls for a few seconds around a device change or a virtual audio driver reconfiguring, and every restart added another thread stuck inside it): the tick is skipped, the dashboard shows "audio service not answering", and the worker is abandoned only after one call has been stuck 20 s - once, even when several callers time out together. The device list on the dashboard tolerates the stall too (it used to crash the app at startup).
- Every page (dashboard, mixer, settings) scrolls when the window is shorter than its content, with a visible scroll bar; the settings form wraps long rows in a narrow window.
- README rewritten around the design principles (goal-driven, preserved dynamics, listen more / act less, learned loudness distribution) with the P / T formula, fallbacks, developer notes and status; now in five languages (简体中文, English, 日本語, 한국어, Русский) with a language bar at the top of each, and fresh screenshots of the dashboard and the mixer.

## 0.3.0 — 2026-10-31

- Remembered gains are only taken from clean moments (steady, or adjusting with no protection cut in the last 20 s); gains bent by a cut were being replayed as the start point of the next sound. All remembered gains are forgotten once on this upgrade.
- The startup master-volume set now happens after the first successful session query (the two Core Audio hangs seen so far were right after it).
- Robustness: if a Core Audio call hangs (the audio service stops answering, e.g. around a device change or a stalled app), the COM worker thread is abandoned and a fresh one takes over with fresh objects, instead of every later call timing out; a single app whose volume call times out is skipped for that tick.
- Intrusions are cut per app: when the protection fires because an app that just started sounding barged in over content that was already playing (a notification over music), the bus cut is undone and only that app is pulled down by the same amount, until it goes quiet (for good if it is in strong mode). The music no longer drops with every ding.
- Modes instead of switches: the bus auto loudness is always on and the dashboard picks which parameter preset ("mode") it runs with; the per-app "Auto" tick is replaced by "strong mode" (every protection cut the app trips pulls its fader down by the excess over B − 5 dB, for good; ticking it does not move the fader). Tool apps are still detected and tagged.
- Parameter presets: the Settings page keeps named sets of all control parameters (new / rename / delete / switch); changes are stored in the active preset.
- Measurement log for analysis: `meters-<ts>.csv` (100 ms rows: momentary / short-term / integrated LUFS, sample peak, gains, phase, B, master) and `apps-<ts>.csv` (per sounding app per 0.5 s poll: peak meter, session volume, bus gain, fader). Nothing is pruned any more (the adjustment log included).
- Adjustment log: every decision the dashboard shows is also written, in the same words plus the apps sounding at that moment, to `adjust-<timestamp>.log` in the config folder (one file per launch, kept 14 days).
- On start the Windows master volume is set to 40 % (Settings, 0 = leave it) and taken as the calibration reference, so there is boost headroom every session.
- Dashboard meters and the listening line now show the perceived loudness (loopback plus the master boost the loopback cannot see), matching the decision log; the B slider bottom mutes.
- The "comfortable" dead band is now asymmetric: up to 3 dB above B and up to 8 dB below B (two settings) count as comfortable.
- New works always jump to the app's remembered gain (or −3 dB for a new app); the "other apps are playing, keep the gain" case is gone — one app at a time is assumed, and the gain is remembered for every sounding auto app.
- The controller now knows the master volume's real headroom (0 dB full scale minus the calibration reference) and never asks for more boost than that, so it no longer believes a quiet source is at B while the master is pinned at maximum; the dashboard marks the boost "(at the limit)".
- Settings apply and save as soon as they change (typed values on Enter / focus-out); the Save button is gone.
- Protection no longer shows a notice: a loud sound is eased down to B + 5 dB within "protection cut takes" (0.3 s, in Settings) and the normal rules resume by themselves once the cut has landed. The loud-sound trigger is one setting edited live from both the dashboard slider and the Settings page.
- Collapsible sidebar: the ‹ button folds the navigation to icons; the state is remembered.
- Volume keys and volume knobs (F11/F12-style media keys, USB/Bluetooth knobs) now move the comfort level B by 1 dB per press instead of the Windows master volume (Settings: on by default, step adjustable; mute is left to Windows; keys pressed while an admin window is in front still go to Windows).
- Comfort level B sliders (dashboard and protection notice) now move in 0.1 LUFS steps.
- One-step-to-B range default is 3 dB (must be larger than the ±2 dB dead band to matter).
- Defaults are now the author's tuned values (listen 5 s, +1 / −0.8 dB steps, ±2 dB dead band, steady re-adjust after 2 loud blocks over B + 6 or 3 quiet blocks under B − 20, protection at B + 13 → B + 5, 1.8 s moves).
- One exe for both languages: on first run the UI follows the Windows display language (Chinese → 中文, otherwise English); switch any time in Settings. The separate English build is no longer needed.
- Dashboard activity card: what the controller is doing right now (ramp from → to over N s, listening progress, protection hold, idle) and a log of its last decisions, for tuning the rules.
- Calibration is one step: set external device and master volume to ~80 %, play music you like, raise the fader from 0 to comfortable → B. The harsh-beep "ceiling A" step and all A-related logic are gone; the onset guard now starts a fixed 10 dB below B (adjustable in Settings).
- Protection: a loud sound is now cut *fast* (0.15 s) down to B + 5 dB (adjustable), measured from the gain actually sounding, and re-corrected once the meter catches up; a cut also overrides a frozen fader hold. The notice stays 10 s, carries the comfort level B slider, and points to the dashboard for the trigger threshold, which now has its own slider there.
- Settings are reset to the new defaults once (config_version 4); profiles and app mixer settings are kept.
- Tool-app detector: an app whose session stays active but sounds less than 10 % of the time over 60 s (IME key clicks, notification helpers) gets its mixer Auto switched off automatically and no longer spoils the "playing alone" test; ticking Auto back on makes that permanent.
- Remembered gains: an app's bus gain is saved continuously while it plays alone (not only once steady), follows B when B is moved, and a known app that starts after silence resumes at that gain directly (1 s move, first decision may cut all the way) instead of the guard ramp from B − 5; the guard ramp now only runs for apps never heard before.
- Timing: every step and the onset guard now ramp over one block length (the "listen" setting); a B-slider move and a new work's jump share one "move" ramp (1 s); the whole-mix silence timeout that re-arms the onset guard is the same 15 s as the per-app work-silence rule (was 2 s).
- Steady state leaves only after 2 consecutive blocks above B + trigger, or 4 consecutive blocks below B − 20 dB (all four numbers in Settings); one loud block alone no longer re-adjusts.
- Dashboard meters read as the distance to B ("B +1.3 dB") once calibrated.
- Settling: within 2 dB of B (adjustable) a step goes exactly to B instead of creeping by the step caps, and the dead band is now ±1 dB (was ±0.5).
- Nudges: the first decision after a new work or onset cuts all the way if too loud; raises stay capped at the step size (the escalating 1x/2x/3x raise was tried and dropped). Onset floor is now B − 5 dB.
- Onset guard no longer boosts: during the 2 s onset the gain is capped at the app's remembered gain (0 dB for an unknown app), so a quiet intro is not pulled up to B only for the real content to blast in and trip the protection; boosting is left to the slow nudges.
- B slider: moving B now sends the gain straight to what the new B needs in one smooth ramp (2 s, adjustable in Settings) instead of the 5 s listen / 0.5 dB nudges, and the sudden-loudness protection is held off until the move has landed, so lowering B no longer pops the notice.

## 0.2.0 — 2026-10-31

- Dashboard "Comfort level B" slider: drag it like a volume knob, the sound follows at once and where it stops is the new B. The music step of the calibration wizard is now optional (B defaults to A + 6 dB until set).
- Controller rewritten around the listen-then-nudge rules: 5 s listening blocks, +0.5 / −2 dB steps with 2 s ramps, ±0.5 dB dead band, no chasing in steady state (re-adjust only when a 5 s block exceeds B + 5 dB), protection cut by the excess (+1.5 dB hysteresis) at B + 10 dB with an auto-closing notice and a threshold fader, faster recovery up to the pre-cut gain. New works start from the gain the app had last time (remembered per process name). Manual fader moves hold that app until its work ends; moving the Windows master volume re-bases B. Faders now run from mute to +15 dB.
- Work detection per app: a new song/video is recognised from Windows media-session metadata (title/artist/album change; pause, seek and artwork updates are ignored), or, for apps without metadata, after 15 s of near-silence followed by sound. Each new work in an auto app closes the current analysis window so it gets its own adjustment. The mixer shows the current work (title — artist, or "Work N").
- Per-app mixer is now a standing feature: ±40 dB faders and a per-app "Auto" switch, working whether the bus auto loudness is on or off. Faders above 0 dB raise the master and attenuate the other apps.
- Apps with Auto off are discounted from the loudness measurement (peak-meter share estimate) so they do not drag the bus gain.
- Mixer faders are compensated in the controller so a -6 dB fader really is 6 dB quieter.
- Calibration source can be any app that is playing; bundled tracks decode off the GUI thread.

## 0.1.0 — 2026-10-20

First public version.

- BS.1770-4 streaming loudness meter (momentary / short-term / gated integrated), verified against pyloudnorm.
- Gain controller: onset guard from silence (A → B over 2 s), 30 s window re-computation with 2 s ramps,
  fast safety limiter (B + 8 dB), explicit master-volume visibility handling.
- Windows backend without drivers: WASAPI loopback + per-app session volume + endpoint volume,
  all COM work confined to one thread.
- Calibration wizard: 2 kHz beep → A, music → B; source can be a bundled track or any app that is playing.
- Per-device profiles, tray, zh/en UI, software simulator for development on any OS.
- PyInstaller single-file exe, GitHub Actions build + release.
